# JEV Information Density v0.8G — Matched-Policy LFM

## Status and question

This is a frozen-backbone, paired-seed comparison of the sealed `R100*` and
`C100*` training banks. It asks whether the frozen curation policy trains a
better dynamic decision compiler than constrained-random selection when bank
size, support/profile, representation, optimization budget, and evaluation
are held fixed. It does not test global optimality or curated-versus-larger
training sets.

The only trainable parameters are those of the v0.5-compatible, dynamic MLP
decision head. The pinned LFM2.5-1.2B-Base backbone remains frozen. Phoenix is
outside scope.

## Frozen inputs and preflight gate

Before model contact, the independent preflight sealed hashes for the run
manifest, `R100*`, `C100*`, `P*`, NewTight-Eval, protected legacy evaluation
indices, source lineage receipts, and the pinned LFM snapshot. It independently
verified 100,000 groups per arm, `D_train = 0.13489`, zero train/evaluation ID
overlap, and all declared P* constraints. The external authorization receipt
is the controlling record; no bank is regenerated by this experiment.

The frozen feature extraction uses the v0.7 LFM adapter, final-layer
`mean_full`, exact-length inputs, batch size one, and no padding. Repeated
training occurrences are retained even when their state/candidate feature
vectors are shared in the cache.

## Training design

The primary candidate surface is `name_definition`. The head is the validated
dynamic MLP with projection width 128 and the existing source-typed L3 loss:
semantic loss, Brier weight 0.25, and certified invariance weight 0.10. The
optimizer is AdamW (`lr=0.002`, `weight_decay=0.01`), batch size 256, exactly
three epochs, with no scheduler or gradient clipping. The terminal epoch is
the primary training point; separate best-epoch selection is not used.

The three seed pairs are 20260927, 20260928, and 20260929. Head initialization
and the deterministic shuffle stream are paired by seed. The arm order is
frozen as R1/C1, C2/R2, R3/C3. Each arm receives exactly 100,000 supervised
occurrences. All stochastic and optimizer settings are shared.

## Evaluation

NewTight-Eval is primary. Legacy dev/test/external slices are secondary and
are selected only by the preflight-sealed cache-row manifests, preserving
their declared row multiplicities. Scalar temperature is fitted only on
legacy-dev exact-generative-posterior rows and is reported beside raw metrics.
Closed choice, independent applicability, and ordinal views are reported in
separate typed panels. Ordinal reports include exact and adjacent accuracy,
expected-rank Spearman correlation, and normalized ranked probability score.
Open-world behavior is not scored by this closed-set training head.

Schema profiles and contradictory-binding probes are diagnostic evaluations;
they do not alter training. Family-level OOD labels, when used, are derived
after freezing the arms by comparing evaluation family IDs with the union of
training-arm family IDs. They are analysis metadata only and never affect
selection, optimization, or calibration.

No single composite score or arbitrary win threshold is defined. Seed-level
values, paired differences, cluster-aware uncertainty, calibration, semantic
ranking, binding, OOD, and intervention behavior remain separately visible.

## Recovery note

The frozen feature pass completed and persisted its cache and all 47 chunks.
An optional Windows peak-RSS telemetry call then raised a `ctypes` process
handle argument error before the receipt was written. A separate recovery
finalizer did not load the model or recompute features; it checked exact tensor
equality between the final cache and all saved chunks, verified the smoke
receipt and input hashes, and wrote an extraction receipt with the wall-time
and peak-CUDA fields explicitly marked unavailable. This has no semantic or
feature impact. The correction is preserved in the external run record.
