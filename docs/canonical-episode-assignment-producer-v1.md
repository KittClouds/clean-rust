# Canonical Episode Assignment Producer v1

Status: implemented.

## Purpose

Canonical Episode Assignment is the first Phoenix-native decision task. The production path now
turns an explicit Atlas Control acceptance of a source-derived event membership into a real native
behavior label and an authoritative graph commit. It does not promote continuity output merely
because the compiler produced it.

## Authority sequence

The desktop exposes the decision inbox for candidate-only continuity events. The operator explicitly
selects an active compatible episode, creates a deterministic new episode, or abstains. The native
transaction then executes:

```text
candidate-only continuity snapshot
    -> deterministic candidate group
    -> immutable native decision receipt
    -> operator outcome authorization
    -> asserted GraphTruthCommit
    -> canonical human-acceptance reward receipt
    -> future-stability horizon observation
```

The candidate group is generated by the existing Episode Candidate Generator v1 and contains every
active compatible episode plus explicit `create_episode` and `abstain` actions. The chosen action is
never inferred from the marked compiler proposal; all unchosen candidates remain frozen in the same
receipt for later ranking and counterfactual work.

The graph commit asserts a canonical event vertex, canonical episode vertex, and
`episode_contains_event` edge when those atoms are not already active. The commit header carries the
decision receipt and operator-authorization receipt, enabling the existing canonical reward producer
without a second inference path.

## Failure shields

- The continuity compiler remains `candidate_only` and `noTopologyCommit`.
- Both the event and every candidate episode must carry `noTopologyCommit = true`; malformed inputs
  fail before the decision log is opened.
- Ambiguous compiler memberships require an explicit operator choice in Atlas Control.
- A second active episode membership for the same event fails before a new behavior label is stored.
- Candidate generation excludes blocked, future, duplicate, and cross-scope episodes.
- The full pre-decision source contract and candidate universe are BLAKE3-addressed.
- Decision identity excludes retry time. Cold retries reuse the original observation time, receipt,
  outcome, commit, and reward identities.
- The write order is decision receipt, outcome authorization, graph commit, then derived reward.
  A retry repairs an interruption without duplicating any immutable record.
- Existing canonical membership returns `already_canonical` and records no redundant graph commit.

## Runtime surfaces

- Rust API: `commit_canonical_episode_assignment`
- Desktop RPC: `commit_canonical_episode_assignment_json`
- Angular request boundary: `canonicalEpisodeAssignmentCommitRequest`
- Atlas action: `commit_episode_assignment`

## Verification gates

Native tests prove:

- the full alternative group is frozen before the selected graph mutation;
- decision, outcome, commit, truth link, and human reward are all durable;
- cold restart returns the same identities without a second write;
- conflicting membership is rejected before a second label;
- candidate topology authority cannot be smuggled through the request.

Angular tests prove:

- the request freezes the exact event and complete episode universe;
- only a unique proposed assignment receives the canonical action;
- ambiguous membership remains non-actionable;
- incomplete native responses fail the authority guard.

## Research boundary

This cut opens future data capture; it does not fabricate historical examples. Frozen Graph Decision
Trajectories remain blocked until the native census reports enough real episode-assignment lineages
for chronological splitting, candidate coverage certification, and leakage checks.
