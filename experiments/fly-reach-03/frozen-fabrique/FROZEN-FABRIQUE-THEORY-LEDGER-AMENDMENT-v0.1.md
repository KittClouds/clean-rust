## Candidate principles

### FF-H1 — Composition

\[
\boxed{C=C(S,I,\pi,T)}
\]

Expressed capability is a property of the substrate/state `S`, interface architecture `I`, presentation or coordinate contract `π`, and task `T` in composition. It is not inferred from substrate content alone.

For the F4 engineering screen, the effective mappings were:

\[
\Phi_D=\rho\circ D,
\qquad
\Phi_{C\Phi}=\rho\circ C\Phi_{\mathrm{canonical}},
\]
\[
\Phi_{C\Phi_u}=\rho\circ C\Phi_{\mathrm{unshared}},
\qquad
\Phi_{C\Phi_s}=\rho\circ C\Phi_{\mathrm{shuffled}}.
\]

They had different measured endpoint scores on the tested panel despite using the same broad relational source material. This is evidence to study the composition, not evidence that the expression is a universal law.

### FF-H2 — Accessibility

\[
\boxed{\text{available information}\ne\text{accessible information}}
\]

Information available in a system may be difficult for a particular downstream interface and learner to use. The F4 result supports this as a candidate principle: CΦ and CΦ-shuffled differed substantially on the tested panel, while their comparison did not add target information to the input stream.

The bounded statement is that this interface family strongly exploits stable role-coordinate binding on this panel. The result does not show that the substrate intrinsically requires canonical coordinates.

### FF-H3 — Interface burden

A façade can impose an auxiliary inference problem before the task computation:

\[
\text{infer interface state}\rightarrow\text{solve target task}
\]

where a better-aligned interface may allow:

\[
\text{solve target task directly}.
\]

For the F4 case, shuffled tuple presentation may require the readout to infer which transformed tuple occupies each semantic role. This is a mechanistic hypothesis motivated by the measured difference, not a demonstrated explanation. Inference-time role-binding interventions are the proposed discriminating next test.

### FF-H4 — Representation monotonicity is not guaranteed

\[
\boxed{\text{more representation}\not\Rightarrow\text{more accessible capability}}
\]

The richer CΦ-shuffled package scored worse than the simpler D baseline in this engineering screen (`0.270111` versus `0.114168` macro balanced error). This motivates testing whether interface organization can add computational burden. The observation is bounded to the tested architecture, tasks, training procedure, and panel; it is not a general monotonicity theorem.

## Measurement separations to retain

Keep classification performance, proposed alignment, delivery-aware alignment, and trajectory endpoint capability as distinct observables. Keep weight-support breadth distinct from how broadly an architectural benefit is distributed. For every Ψ-style result, report leverage ESS and top-1%, top-5%, and top-20% leverage shares. The F4 panel had near-uniform q weights but highly concentrated Ψ leverage; those are different forms of support.

Preserve each assignment effect rather than presenting the average as a uniform architecture effect. The observed `CΦ − D` effects in assignment order `1100, 1010, 0110, 1001, 0101, 0011` were:
