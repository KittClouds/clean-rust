# ff-s15-c1-observers-01 — System 1.5, rung C1: real observers behind the C0 controller

C1 plugs the existing Rung 0 observers (the four carry-forward surfaces of the frozen LFM2.5-230M-Base, with their saved linear
`decision` and `action_type` heads) into the C0 deterministic runtime, and asks whether the black-box premise survives contact:
**does observer confidence carry enough information for a fixed, deterministic policy to route safely?**

- Question, data, split, controller, threshold rule, criteria and verdict rules: [PREREGISTRATION.md](PREREGISTRATION.md) (written before HOLD was scored).
- Result and honest reading: [RESULTS.md](RESULTS.md). Receipts: [results/](results/).
- Headline: preregistered verdict **PARTIAL**. Confidence is strongly informative and the harm cap transfers to unseen worlds; the cheap tier executes a correct
  action on only ~6% of rows at a 5% harm target; ASK is never resolved.

Development evidence on BANK-v1 DEV only. **No TEST row, prediction or label was read**, and TEST has been opened twice already, so this cannot be a confirmatory result.

## Depends on

- C0 (`../ff-s15-c0-runtime-01`), imported unchanged; its source hash is recorded in every freeze and report, and scoring refuses if it changed.
- The Rung 0 lock `daa0406aa3f7…` and its cached artifacts on `D:\phoenix-target-overgraph\bank-v1-surface-extremes-20260929` (override with `S15_C1_SWEEP`, `S15_C1_RUNG0_LOCK`).
  The lock lives on branch `codex/lfm-230m-specialization-atlas-2026-09-29`, not on this branch. Every artifact C1 reads is re-hashed against the lock first.
- No GPU and no language model: the heads are linear, so their outputs are rebuilt from cached features with numpy. The rebuild matches the sealed Rung 0 predictions on all 24,000 DEV rows.

## Run it

```bash
python run_c1.py prepare     # ~3 min: verify hashes, rebuild DEV probabilities, reconstruction gate, mint C0 records (no HOLD numbers)
python run_c1.py calibrate   # fit thresholds on CAL rows only, write 20 policies, freeze (preregistration + C0 + thresholds hashes)
python run_c1.py score       # ~1 min: HOLD through the real C0 runtime; refuses if the freeze changed or HOLD was already scored (--again records a rescore)
python tools/make_results.py # RESULTS.md and results/ from the report (prose guards fail if the report stops supporting a claim)
python -m unittest           # 14 tests on synthetic data: fitting, outcomes, split, and numpy-vs-C0 agreement row for row
```

`evidence/` (arrays, worlds, policies) is git-ignored and regenerated by `prepare` and `calibrate`; `results/` is the tracked receipt set.

## Layout

```
c1/common.py     constants, paths, C0 import, hashing        c1/fit.py       Wilson bound, threshold fitting, numpy rules, outcomes, permutation control
c1/rung0.py      verify artifacts against the lock, load heads   c1/policy.py    the controller as a C0 RuntimePolicy
c1/data.py       DEV rows, truth, leak-free split             c1/records.py   observations and decision vectors
c1/observers.py  rebuild probabilities, C0 contracts and bundles  c1/score.py     runtime scoring worker, criteria M1-M4, verdict
run_c1.py        the three stages                             tools/make_results.py, RESULTS.template.md
```

## What would make C1 confirmatory

A fresh sealed split: new BANK seeds, truth withheld until predictions and thresholds are sealed, then the same frozen procedure scored once.
That is a BANK-side build (Lexi's ladder) and has not been done.
