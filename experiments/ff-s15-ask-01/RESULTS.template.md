## What to take from it

- **C1's "ASK is absent" was too strong; the accurate version is weaker and narrower.** The existing head already ranks ASK rows (AUROC about 0.8, AP about {b_ap} against a prevalence of {prevalence}); it never reaches the ≥ 0.80 precision C1 demanded, because that bar was
  set for executing actions, where a false positive is harm. For ASK a false positive is an unnecessary question, and at about 50% precision the cheap tier can already catch {b_r5} of the cases that need one (existing head, matched precision 0.5).
- **A dedicated head on these surfaces does not change that.** Training specifically for ASK, linear or with a tiny MLP, moves AP by about {m_ap_pts} points ({m_ap_gain} relative, for the MLP) and does not open a higher-precision regime.
  The information for "a needed fact is missing" is not much better exposed to a bigger readout than to the existing one, which fits what ASK is in BANK: in TRAIN every ASK row has exactly one missing, requestable fact
  (`missing_fact_count` = 1.0, always `REQUEST`), so ASK is a *negative-evidence* problem — detecting an absence — that a pooled 230M representation of the whole text exposes only weakly.
- **For the representation ladder:** the useful new evidence for ASK is unlikely to come from more surfaces or bigger heads on the same pooled vectors (C2a and this rung both say so). It has to come from capabilities that compare the goal
  against the facts actually present — the NER/NLI direction (unresolved entities; NLI UNKNOWN as "insufficient support") — i.e. genuinely different trained tasks.
- **What the rung did not do:** it did not test whether the existing NLI head's `P(UNKNOWN)` already carries independent evidence for ASK. That is a cheap oracle-headroom census on vectors that mostly exist, and the natural next question if you want one.
  Not run, not proposed as a rescue of this rung.

## Sensitivity, and one thing worth seeing

The MLP on `final_plus_mean` passes A2 and A3 (a fitted rule of {fpm_asks} asks at {fpm_p} precision and {fpm_r} recall, α = 0.50) but not A1 ({fpm_ap} against {fpm_bap} AP), and it is not the preregistered primary. Read it as: a usable-looking ASK rule exists
on that surface, but it is not a gain over the existing head there either. Numbers for all four surfaces are in the criteria tables.

## Process notes (disclosed)

- **Addendum 1 (recorded before calibration):** the first training run, following the preregistered recipe exactly, did not converge — final TRAIN loss about 0.49 against 0.191 for a constant predictor, output bias at −0.52 against the −3.0 the prior needs.
  It was diagnosed on TRAIN rows only, fixed by initialising the output bias at the TRAIN prior logit, and retrained before any dedicated-head result on DEV existed. No criterion or verdict rule changed.
- A first training run also crashed on a read-only memory-mapped array (single-primitive surfaces); fixed by copying the features. No result existed then.
- The MLP was trained and scored only because the preregistered rule required it (linear not USEFUL and CAL AP ≥ 0.10). Each head's HOLD was scored once.

## Limits

DEV only, and HOLD has now served C1 and this rung, so it is not virgin: the confirmatory answer needs the fresh sealed split. One seed, BANK is synthetic, a single hidden layer, no calibrator beyond thresholding.
The A2 bar (precision ≥ 45%, recall ≥ 25%) is a judgement about what a useful cheap ASK tier is; the frontier tables above let a reader apply a different one. The reason head (what kind of information is missing) was not attempted.
