# E012 task construction specification v1.1

**State:** frozen before scored task fixtures. **Model contact is not authorized.**

This specification applies E012 bank amendments A04 and A05 to the v1.3 family design. It preserves the 48 task families/items, 26 conditions per task, and 1,248 projected frames.

## Executable task bank

Build four action candidates for each of 48 isolated Rust consumer-code tasks over the pinned `bytes`, `clap`, and `serde_json` snapshots. Apply patches only in clean task-owned overlays. Run 192 candidate-task checks and 48 base-task checks using the A04 suite schedule. Candidate completion labels come only from these executable checks and the locked task truth construction. Compiler errors are construction failures.

The bounded-prefix task's scored assertion checks both prefix bytes and shared backing storage. Generic failures in two cloned harnesses receive field-specific assertion messages; the assertion predicate is unchanged and each modified overlay is hashed.

## Presentation coordinates

The source fixture stores candidate options in a seeded producer-native sequence. The four task rows in each family use a seeded Latin schedule built by deterministic backtracking. Action IDs and primary-gold positions are exactly balanced across the four rows. The generator minimizes passing-candidate count spread across positions; the feasibility matrix makes exact equality impossible for two multi-valid families, and every position remains mixed. Abstention families have no gold position. The coordinate-control condition uses the reverse sequence. The donor-coordinate condition transfers the role-to-position mapping from a nonself member of the same `pair_id` onto the recipient's IDs. Each condition is independently presented and receipt-bound. The pre-contact audit reports action-ID and position validity frequencies and rejects any perfect correctness indicator within an action family.

## Donor selection

Channel swaps use nonself same-pair donors. Prefer a donor differing on the swapped channel while minimizing other-channel differences. If no such donor exists, use the next same-pair task as a declared isomorphic sham. The sealed truth index records donor identity; the observer frame does not.
