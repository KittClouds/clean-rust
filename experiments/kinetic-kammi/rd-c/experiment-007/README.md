# R&D-C Experiment 007 — Query Value Transfer

E007 asks whether E006's feature router learned portable inspection value or fit quirks of its synthetic bank. It trains value models on eight development worlds, freezes them, then evaluates on sixteen independently seeded held-out worlds. The held-out bank recipes vary observer error, inspection reliability, contradiction quality, Unknown/Failed rates, source staleness, query cost, and domain identity.

Five paired lanes use the same public episode bank and exact call budgets: development domain table, smoothed domain table, feature value router, matched random, and no inspection. An evaluation-only oracle ranks the realized counterfactual result after labels and source fixtures are unsealed. The oracle has no route authority.

The feature router reuses E006's fixed eight-feature schema; its scoring function receives only that feature vector and public query price, used to rank estimated benefit per cost. Bank ID, domain ID, source fixture state, correct action, and evaluation labels do not enter that interface. Plans are frozen and written before held-out outcomes are loaded for scoring.

The `rdc-runtime-contracts-v1` crate is a separate local package extracted from E006's stable-ID paid-action receipt flow and typed inspection outcome boundary. E006 sources and sealed run artifacts remain unchanged.

All worlds and inspectors are synthetic, deterministic proxies. A transfer result applies only to these preregistered world generators and feature semantics.
