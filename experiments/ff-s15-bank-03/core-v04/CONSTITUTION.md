# BANK-v3 v0.4 — prospective core/human amendment

Adopted 2026-10-02 under the owner's end-to-end construction authorization.
Prior scaffold, target-contract v1, V2-0 receipts, and O1 negative permission
result remain immutable history. This amendment precedes corresponding code
and corpus construction. It does not rewrite V2 source or import V2 rows.

## Releases and provenance

BANK-v3-core is explicitly SYNTHETIC_ONLY. G14-CORE requires zero external
roots/rows and root generation through the hash-pinned V2-compatible simulator,
algebra, requirements and witness machinery. A new release namespace changes
every generation RNG stream; no ancestor rows are consumed.

BANK-v3-human remains pending. It requires external roots, permission-cleared
sources, admissible transformation/reconstruction witnesses, identity and
lineage receipts, and the original human-source provenance gates. No core seal
is a human seal; O1's negative result is not rescinded.

## Corrected target dispositions

Disposition, reason and first_action_type are admissible. First action type is
classification of the selected EXECUTE action's type, not named-candidate
selection; the historical 0.9032 is defined score headroom, not demonstrated
learnability and not a proof of the historical MOVE bottleneck. Reason B3
0.0382 is slightly above majority 0.0342: weak lexical recovery, not proof of
textual impossibility.

Requestability and missing_cardinality retain mandatory within-stratum
reporting. The former is stratified by renderer/length/temporal wording; the
latter by hidden count, requirement count and irrelevant-hiding intervention.
Conflict stays DIAGNOSTIC_ONLY after repair/recheck in this release. Promotion
would require a later independent disposition. TRANSFER and WAIT have support
reporting only, regardless of any increased core support.

The old B3 100k TRAIN-head fit has no guaranteed bias direction on DEV. A full
fit could beat the winner for any target. Negative cue findings remain qualified.
B0 exact replay validates the target/instrument derivation, not every learner or
renderer. This build measures no neural model learnability.

## Bounded core curriculum and contracts

Initial model-ready release: 12,000 TRAIN, 3,000 DEV, 3,000 evaluation canonical
roots, each with two meaning-preserving renderings. The 18 existing intent
families are acquisition cells, never labels. Alternate shallow (1–2) and
deeper (2–4) plan requests for plan-bearing cells. Plan-free cells retain the
ancestor's valid generation ranges. Failed attempts are receipted; no semantic
relabeling or selection against a model is allowed. Disjoint root namespaces,
structural/context deduplication and paired-family grouping precede final splits.
Evaluation uses held renderer families H1–H4; TRAIN/DEV use V1–V8.

Weights: equal independent target-family blocks; available action endpoint
weight 0.5; diagnostic conflict weight 0; aliases share one source unit.
Requestability/missing-cardinality are supervised only where canonically
available; metrics remain stratum-restricted. No bank-defined vector scaling.
Per-class/slice DEV support below 200 is UNDERPOWERED. No numerical capability
promotion is implied by a bank seal. Counts/support are always reported.

Every root carries all ten derived axes: binding, evidence_support,
counterevidence, missing_requirements, conflict, composition_depth,
transition_depth, candidate_comparison, globalization, nuisance_invariance.
Definitions are explicit in the machine contract and derivation code.

All canonical available actions are retained, ordered lexicographically by
content-derived action ID. Selection is eligible only on EXECUTE rows; its
scalar index must resolve to the selected ID. WAIT is an action, not a fabricated
NOOP. Environment shortest-path first actions and policy-admissible optimal
sets are separate fields. Ineligible/non-solved/already-satisfied rows have an
empty operational optimal set and no optimal-hit denominator. No empty set
is silently counted as a successful hit.

## Repair and gate scope

Use one neutral assertion/report sentence grammar for visible facts and
reports, retaining source and confidence semantics. Replace the four known
target-coupled phrases in both report and information-policy realization.
Choose renderer family/style only from root index/renderer slot, never labels.
No fixed report phrase presence can encode conflict by construction.

Bookkeeping intervention: hide a seeded subset of nonrequired, open-slot,
currently visible facts, exclude required/support/report facts, and independently
rederive labels. Every accepted intervention must preserve the six core targets.
Absence of eligible facts is recorded, not represented as an intervention.
Do not alter required observations to agree with omniscient truth.

Gates cover 100% of emitted rows: semantic derivation, simulator/refsim
transitions, candidate alignment, renderer realization, root replay, ancestry,
split leakage, input firewall and bookkeeping preservation. G19 checks the
complete known four-phrase signature and all declared B4 phrase indicators on
TRAIN/DEV; targets reaching macro-F1 0.80 from the declared cue instrument stop
the seal until prospectively repaired. This is a bounded cue test, not proof
against every imaginable lexical learner. Record B4 length/cue learner and
restricted targets by strata. Never turn a nominal seal into a universality claim.

Protected evaluation truth is created and checked only by authorized bank
construction/replay tools. Model-contact handoffs contain public evaluation
inputs only; TRAIN/DEV expose supervision. No model weights are opened and
no corpus adjustment uses model behavior. Sealing/replay include protected
truth under this construction contract; downstream training has no grant to it.

A failed engineering attempt is preserved. Repairs version the affected build
identity before regeneration. No final seal exists while any required gate fails.
