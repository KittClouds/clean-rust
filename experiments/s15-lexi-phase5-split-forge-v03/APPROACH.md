# Lexi Phase 5: Split Forge

Lexi owns computation over candidate-relative state. BANK-v3-core is the main
TRAIN/DEV population; BANK-v1 remains historical evidence. No Frizz access organ
or new surface is added.

The bridge is the earned causal Phase-0 graft family on `final_plus_mean`, with
only the v3 action vocabulary expanded. Observable action arguments use four
type-specific slots and deterministic entity ordinals. All canonical candidates
survive; the maximum is 171. This is a new v3 bridge identity, not a replay of v1
scores or a claim that the v1 trained weights transfer unchanged.

V3 has a genuine nonbinary missing-count target. It receives SmoothL1, while
binary missingness and count share one canonical-source unit of supervision.
Conflict is excluded from training. Unsourceable ABI heads remain masked.
Renderer prediction consistency applies to available binary heads and aligned
candidate/action distributions; no categorical distribution is invented for the
count output. The original raw latent matching loss remains retired.

After bridge fitting, freeze it. Train A and B with identical initial mean
recurrence and output projections, identical batches, optimizer schedule, final
plus intermediate losses, and T=4. A is deterministic; B adds a learned diagonal
Gaussian scale and samples one trajectory. No beam, particles, chain selection,
ensembling, adaptive halting, or stochastic rescue. Bridge checkpoint selection
uses the declared deterministic DEV objective. Both recurrent arms use fixed
final epoch 20; their sampled DEV curves are diagnostic and cannot select weights.
This prospective v03 correction preserves the untrained v02 files and specification.

The flight recorder reports initialization and trained linear/tiny-MLP
accessibility, production targets, inference-only path ablations, exact logged
action, nonempty optimal-set hit, depth slices, renderer correctness decomposition,
candidate preservation, state diversity, update RMS, stochastic variance, and
runtime costs. DEV predictions are saved so an independent process can recompute
the metrics. Paired-root bootstrap differences show uncertainty without changing
selection. A survivor requires repeated terminal/deep-slice gains across all three
declared trajectory seeds and no detected semantic loss under those intervals;
that is a bounded engineering disposition, not proof of zero degradation.
Empty optimal sets are support-only and excluded from hit ratios.
Only MOVE currently clears the DEV action-type reliability floor; the other
action types cannot support capability claims.

No composite score, cross-lane winner, protected EVAL contact, or corpus tuning
against model behavior. A non-improving stochastic arm is retired as constructed.

All caches, checkpoints and journals live under the C: NVMe run directory. A busy
GPU is allowed to finish its existing job before this run takes the device.
