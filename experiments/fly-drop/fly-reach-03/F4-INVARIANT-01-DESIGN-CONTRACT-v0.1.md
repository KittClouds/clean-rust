# F4-INVARIANT-01 — Design Contract v0.1

**Title:** Permutation-Invariant Relational Sidecar Qualification Comparison  
**Status:** design only; no tasks, seeds, code, fits, or run namespace created  
**Purpose:** compare a frozen sorted relational representation with a shared set encoder on fresh ordinary qualification tasks.  
**Measured REACH-03:** closed.  
**PHENO:** unchanged and closed.

## 1. Question and claim ceiling

The question is:

> Does replacing the sorted relational sidecar with a shared, sum-pooled set encoder improve held-out-task-block extraction of reference polarity on fresh ordinary qualification tasks?

The primary contrast is `S - D` in pooled out-of-fold IPW-balanced error. Negative values favor S. This is a comparative qualification experiment, not an F4 calibration promotion trial and not a measured REACH-03 result.

The set encoder is permutation-invariant with respect to the four relational tuples. The complete predictor is **not claimed to be cue-permutation invariant**: the unchanged 66D base retains absolute cue-slot fields. The claim ceiling is therefore about the relational sidecar's representation and its utility conditional on that common base.

No result from this experiment establishes a task-symmetry law, native-interface availability, a causal learning benefit, biological mechanism, or a trajectory improvement.

## 3. Frozen information set

Both arms receive the same admissible information:

1. the frozen clean base `x_base ∈ R^66`, with the exact source-field selection and ordering in the referenced F4-SYMMETRY-01 contract; and
2. the same four cue tuples, each containing the six fields

   `r_c = (I_ic, r_c, I_ic*r_c, delta_c, I_ic*delta_c, r_c*delta_c)`,

   where `I_ic` is cue-edge incidence, `r_c = y_c*a_j`, `delta_c = p_cj - 0.5`, and `p_cj` is generated by the contract's standalone ordinary-forward calculation.

No expected-score intermediate, reference-only coefficient, `g`, `Y`, target-derived feature, or reference helper output may enter either arm's predictors. Targets are used only as training labels for training folds and as held-out scoring truth after prediction lock and integrity pass.

The four tuple values must be identical between arms before their arm-specific presentation. The three continuous tuple components use the existing per-fold training-only component normalization pooled across all rows and cue positions. The 66D base uses the existing per-fold training-only normalizer. Discrete tuple fields retain the existing encoding. Normalization values are applied unchanged to held-out rows. There is no post-pooling normalization in S.

## 4. Arms

### D — frozen sorted-sidecar comparator

D is the existing 90→128→64→1 float32 MLP and sorted relational sidecar. Preserve its tuple definition, canonical comparator, normalization, GELU implementation, binary cross-entropy training rule, Adam settings, 200 epochs, batch size 2048, contiguous frozen row order, and no-shuffle policy. Refit D on the new leave-one-block-out training partitions; do not reuse old D predictions or weights.

### S — shared set encoder

For each cue tuple, apply one shared `6→16` affine map and GELU:

`h_c = GELU(W_phi r_c + b_phi)`, with `W_phi ∈ R^(6×16)` and `b_phi ∈ R^16`.

Sum the four embeddings, without sorting or averaging:

`h_set = Σ_(c=1)^4 h_c ∈ R^16`.

Concatenate with the normalized common base and use the readout:

`logit = rho([x_base, h_set])`, where `rho` is `82→128→64→1`, with GELU after the first two affine layers and a linear scalar output.

The same `phi` parameters process every cue tuple. There are no cue-position embeddings, cue-ID tie breaks, additional task fields, or rank slots. The model is invariant to any permutation of the four tuple inputs when `x_base` is held fixed.

### Parameter and training-budget match

D has 19,969 trainable scalar parameters. S has 19,057, including the shared `phi` network, or 4.57% fewer parameters. This is within the frozen 5% matching band. Do not enlarge either model to equalize parameter counts.

Both arms use float32, the frozen GELU and BCE-with-logits learning semantics, Adam (`lr=0.001`, `beta1=0.9`, `beta2=0.999`, `epsilon=1e-8`), 200 epochs, batches of 2,048 in frozen global row order, contiguous batches, no shuffling, and the same final-short-batch rule. No early stopping, outcome-dependent tuning, ensembling, prediction flipping, or extra epochs.

Use three prospectively fixed paired initialization replicates per held-out fold. Within a fold and replicate, D and S use the same predeclared initialization seed key and the existing fan-in-scaled normal initialization with zero biases; tensor bytes need not match because their layer shapes differ. Freeze the key derivation and exact generator behavior in the implementation specification before fitting. Retain every replicate; do not select a favorable one. The resulting fit matrix has `12 blocks × 3 initialization replicates × 2 arms = 72 fits`.

## 5. Fresh ordinary qualification panel

Use exactly 12 fresh ordinary task blocks from the frozen qualification task generator. Use the same task semantics, training horizon, delay, frozen substrate panel, side panel, selected-coordinate manifest, and U* construction as F4-CALIBRATION-02. The panel comprises the existing nine substrates by two sides and the existing 64 selected coordinates per substrate-side cell. Each task block uses four cues, 8,192 trials, and delay 12.

Do not structurally screen, pattern-balance, outcome-screen, or replace blocks. Draw and freeze all task and simulator seeds from a new domain-separated namespace before native collection. Keep every generated block, including blocks with empty U* or only one target class. Do not use RUN4, SYMMETRY-03, QPROMO1, or QPROMO2 outcomes to choose seeds or tasks.

Before any outcomes are opened, freeze a minimum support rule of at least 10 of 12 task blocks containing both nonzero target classes on U*. If fewer than 10 blocks meet that rule, disposition is `NOT_EVALUABLE_SUPPORT`; retain all collected blocks and report pooled values descriptively, with no replacement blocks.

The support rule does not select which blocks are fitted. Always execute the full predeclared 72-fit matrix. If support is below 10 blocks, the model outputs remain qualification diagnostics only and cannot advance S.

## 6. Folds, fitting, and truth firewall

Use 12-fold leave-one-task-block-out validation. Each fold holds out the complete task block across all substrate-side cells. D and S in a fold receive identical training rows, labels, row order, held-out rows, and fold-normalization source rows. Fit all three paired initialization replicates for both arms.

Fit labels use only nonzero `Y` rows in training folds, with `Y=-1` encoded as 0 and `Y=+1` encoded as 1. Match the existing F4 training loss: unweighted BCE; inclusion probabilities do not weight training. Prediction is positive only for `logit > 0`; zero logits predict negative.

Write and hash every held-out prediction stream, fit receipt, and complete fit manifest before joining held-out target/reference truth. An independent integrity pass must verify the complete 72-fit grid, unique row keys, exact D/S paired fold rows, finite features/weights/logits, expected checkpoints and hashes, and unchanged source inputs. Failed integrity stops analysis. Do not inspect comparative outcomes during task generation, native collection, or fitting.

## 7. Outcomes and fixed readout order

The primary score for arm `a` and initialization replicate `r` is pooled out-of-fold IPW-balanced error over all U* rows:

`epsilon_(a,r) = 0.5 * Σ_(Y=+1)(q*error)/Σ_(Y=+1)q + 0.5 * Σ_(Y=-1)(q*error)/Σ_(Y=-1)q`,

where `q=1/p_inclusion`. Report

`Delta_(S-D) = mean_r(epsilon_(S,r) - epsilon_(D,r))`.

Negative values favor S. Report each of the three paired replicate contrasts as well as their mean. The primary comparison is qualification-level and descriptive; do not attach a confirmatory population claim.

Report results in this order:

1. pooled D and S IPW-balanced error, `Omega_hat = max(0, 1-2*epsilon_bal)`, unclipped `1-2*epsilon_bal`, and paired `Delta_(S-D)`;
2. per-block paired balanced-error differences, averaged across initialization replicates; blocks without both classes have undefined balanced error and remain visible;
3. blockwise signed margins using the equal-class IPW rule when both classes occur, with the one-class `q`-weighted `Y*logit` diagnostic separately labeled;
4. capability-weighted polarity `Psi` for D, S, native polarity, and reference-sign oracle, where `m=abs(native_proposed_delta)`, `q=1/p_inclusion`, `w=q*m*abs(g)`, `A_w(s)=sum(w*1[predicted_sign=sign(g)])/sum(w)`, and `Psi(s)=2*A_w(s)-1`;
5. for every reported `Psi`, leverage concentration: `ESS=(sum(w))^2/sum(w^2)` and the leverage mass shares in the top 1%, 5%, and 20% of rows, ranked by `w`;
6. delivery-aware `eta_del` as a secondary local diagnostic, using the frozen weight bounds and the existing F4-SYMMETRY-01 delivery equation.

Classification error, signed-margin orientation, capability-weighted polarity, and delivery-aware alignment are distinct outcomes. `Psi` is a first-order reference-alignment quantity, not a guarantee of nonlinear multi-step trajectory improvement. No trajectory is run with predicted signs.

## 8. Qualification decision fork

The comparison is eligible to nominate S for a **separate fresh ordinary-task F4 calibration promotion trial** only when all of the following hold:

- at least 10 of 12 blocks are class-complete on U*;
- mean `Delta_(S-D) < 0`;
- S has lower pooled error in at least two of the three paired initialization replicates; and
- the across-replicate mean blockwise difference favors S in at least `ceil(2E/3)` of the `E` class-complete blocks.

This is a finite candidate-advance rule, not a significance test or a calibration pass. If support passes but the rule does not, close this set-encoder candidate as `NO_CLEAR_COMPARATIVE_ADVANTAGE`. A candidate that advances must still pass the original, separately sealed learned-F4 calibration gate on fresh ordinary tasks (`epsilon_bal ≤ 0.10`, `Omega_hat ≥ 0.80`, required block support and per-block criterion). No result here opens measured REACH-03.

If calibration fails, preserve the result and close this architecture candidate. Do not alter the base, tuple, pooling, architecture, optimizer, task distribution, support rule, or promotion thresholds under the same identity.

## 9. Invariance and integrity fixtures

Before fitting, pass a deterministic representation-only fixture that feeds all 24 permutations of each fixture's four tuples to S while holding the same `x_base` fixed. S logits must agree with the identity-order logit within the frozen tolerance `abs(delta) ≤ 1e-6 + 1e-6*abs(reference_logit)`. No target or reference value is read by this fixture. This tests the set branch's numerical permutation invariance; it does not test target symmetry or the complete predictor under a joint task/cue transformation.

Also verify the following before fitting:

- row keys, U* eligibility, inclusion probabilities, and target bytes reconcile with the frozen source contract;
- D and S consume the same four normalized tuple values and the same normalized 66D base on each row;
- S applies one shared `phi` to all four tuples and contains no position-dependent parameter;
- parameter counts are exactly the declared values and within 5%;
- all initialization keys, normalization artifacts, fit rows, and fit order are frozen before fit 1;
- the three replicate streams are all retained, prediction streams are hash-locked, and the integrity pass precedes truth opening.

Any discrepancy stops this identity before outcomes. No task or fit replacement is allowed.

## 10. Interpretation boundaries and downstream work

If S meets the comparative advancement rule, only a separate calibration promotion trial becomes eligible for design. Its task panel must be fresh and ordinary, and its original calibration gate remains unchanged. If S does not advance or fails that promotion trial, close this architecture candidate without tuning it under the same identity.

Measured REACH-03 remains closed until a learned F4 calibration candidate independently passes its frozen promotion gate and a separate measured-run seal is authorized. No controller, PHENO recovery experiment, biological promotion, or claim about the native learner's accessible information follows automatically from this comparison.

The branch's exact claim ceiling is:

> On the declared fresh ordinary qualification distribution, the shared set-encoded relational sidecar did or did not improve held-out polarity extraction relative to the frozen sorted-sidecar comparator, under the same admissible base and tuple information and the declared estimator/training budget.

This contract authorizes design and implementation specification only. Task/seed generation, model code, collection, fitting, and creation of a run namespace require a later explicit step.
